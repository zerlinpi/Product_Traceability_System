# SOP · 管理员

## 每天

| 时间 | 做什么 | 怎么看 |
| --- | --- | --- |
| 上班 | 确认服务能登录 | 打开首页 |
| 上班 | 看昨天有没有异常推送 | 系统设置 → 审计记录，筛 `*_PUSH_UNKNOWN` 与 `*_FAILED` |
| 下班前 | 确认今天的备份生成了 | 看 `exports/backups/` 最新文件时间 |

> **`PO_PUSH_UNKNOWN` 需要人工处理**：去领星按单号核对，
> 确认没建单再让运营重推。**不要直接重推。**

## 每周

1. `python manage.py integrity-check` —— 期望 `[OK]`
2. `python manage.py audit-verify` —— 期望通过
3. 确认异机副本与本地一致
4. 检查磁盘剩余空间

## 每月

1. **恢复演练**：备份 → 校验 → 恢复到隔离库 → 抽查（见 [08 备份与恢复](../08-备份与恢复.md)）
2. 复查用户列表：**离职人员是否已停用**
3. 复查仓管的产品范围是否仍然合适

## 有人入职

1. 基础资料 → 用户管理 → **新建用户**
2. 选角色；仓管可勾选产品范围
3. 把用户名与初始密码交给本人（**他首次登录必须改密码**）

## 有人离职

1. 用户管理 → 找到账号 → **停用**
2. 不要删除——历史记录需要保留归属

## 领星凭据变更

1. 系统 → 系统设置 → 填新的 **AppID / AppSecret**
2. 点 **测试连接**
3. 成功后**立即推送一张测试单**验证全链路

## 升级

```bash
python manage.py preflight      # 会自动生成升级前备份
# 停服务、替换程序文件（保留 data/ 与 settings）
python manage.py postflight
```

> 升级前**必须**确认备份可用。降级只能靠恢复备份。

## 出问题时的顺序

1. 先看**审计记录**——大多数问题能直接看出是谁做了什么
2. 再看 [09 故障排查](../09-故障排查.md) 对照现象
3. 涉及数据不一致 → **先备份**，再排查
4. 涉及领星重复单据 → 先核对领星，再决定是否删除多余单据
