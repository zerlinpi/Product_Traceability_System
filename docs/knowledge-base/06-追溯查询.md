# 06 · 追溯查询

## 扫码查询

菜单：**历史记录 → 扫码查询**

**只读页面**，不产生任何数据变更。

1. 扫描批次二维码。
2. 查看结果。

页面上会显示：

| 内容 | 说明 |
| --- | --- |
| **批次码** | |
| **产品型号 / 名称** | |
| **计划台数** | 生成批次时填的 |
| **已登记台数** | 现场登记的数量 |
| **质量状态** | 待检 / 已放行 / 暂扣 / 作废 |
| **反向追溯** | 这批**用了哪些原材料**，各用了多少 |
| **正向追溯** | 这批料**流向了哪些产品** |

## 两个方向的追溯

### 反向：产品 → 原材料

「这台机器用了哪批料？」结果里每条会显示部件名称、规格、供应商、批次号与**消耗数量**。

> 消耗数量按**登记台数**算，不是计划台数。登记 50 台、每台用 3 个，消耗就是 150。

### 正向：原材料 → 产品

「这批料都用到哪里去了？」在**供应商详情 → 到货批次**里点 **正向追溯**。

> 出质量问题时用这个：一批料有问题，能一次查出所有受影响的成品。

## 产品查询

菜单：**历史记录 → 产品查询**。按产品查看生产批次与供应批次族谱，不依赖扫码。

## 历史单件追溯

如果记录了单机（设备 SN），可以用**识别码**查这台机器单独的族谱。

## 批次登记记录

菜单：**历史记录 → 批次登记记录**。按批次码或产品搜索。

> **列表只显示最新 500 条**。超过时页面顶部会提示
> 「仅显示最新 500 条，共 N 条」，请用搜索框缩小范围，或导出完整数据。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 扫码查不到 | 确认扫的是**批次二维码**，不是生产二维码 |
| 反向追溯是空的 | 该批次不是通过「批次生成」创建的，见下方说明 |
| 列表看不到更早的记录 | 用搜索框筛选，或导出 |

> **关于反向追溯为空**：系统的「批次生成」会绑定 BOM 物料并扣减库存；
> 而「生产订单」自带批次不绑定物料。若某批次没有消耗记录，
> 说明它不是通过「批次生成」创建的。这是当前设计，需要业务上确认是否要合并。
