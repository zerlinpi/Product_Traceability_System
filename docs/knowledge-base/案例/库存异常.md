# 案例 · 库存对不上

## 现象

- 原材料**可用数量**比预期少
- 成品入库数量与生产记录对不上
- 系统提示库存不足，但账面看着够

## 按这个顺序查

### 1. 先分清是哪一种库存

系统里有**两本账**，不要混：

| 账 | 记什么 | 在哪里看 |
| --- | --- | --- |
| **原材料库存** | 供应商送来的料，被生产批次扣减 | 供应商详情 → 到货批次 |
| **成品库存** | 工厂生产并入库的成品 | 采购生产 → 扫码枪入库 |

> 「供应收货」记的是**料**，「扫码枪入库」记的是**成品**，两者分开记账。

### 2. 原材料可用数量少了

**正常原因**：生成生产批次时会扣料。

```sql
扣减量 = 计划台数 × 该部件的每套用量
```

例如每套用量 2、计划 100 台 → 扣 200 个。

**核对方法**：

1. 打开该到货批次，看**到货数量**与**可用数量**的差。
2. 去 **历史记录 → 批次登记记录** 找用这批料的生产批次。
3. 用 `计划台数 × 每套用量` 对一下，看差多少。

**不正常的情况**：

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 可用数量是**负数** | 并发扣减出错 | **立即报管理员**，这是严重问题 |
| 扣了料但没生成批次 | 事务未回滚 | 报管理员，查审计记录 |
| 同一批次扣了两次 | 重复提交 | 系统有幂等保护，若仍发生请报管理员 |

### 3. 成品入库数量对不上

**核对方法**：

1. **采购生产 → 生产订单**，看该订单的计划台数与已入库数量。
2. **采购生产 → 扫码枪入库**，看入库记录。
3. 两者应该一致。

**常见原因**：

| 现象 | 原因 |
| --- | --- |
| 入库少于计划 | 还没入完，正常 |
| 提示「已按计划入库完毕」 | 重复扫码，系统拦住了 |
| 入了两次 | 系统有幂等保护，若仍发生请报管理员 |

### 4. 看看审计记录

**系统设置 → 审计记录**，按时间筛选，能看到：

- 谁在什么时候生成了批次
- 谁登记的、谁放行的、谁入库的
- 有没有删除操作

## 绝对不能做的事

| 不要 | 为什么 |
| --- | --- |
| 手工改数据库 | 会破坏审计链与追溯关系 |
| 直接改「可用数量」 | 系统按生产批次自动扣减，手工改会让账实不符 |
| 删除重建记录来「修正」 | 审计链会断，历史追溯失效 |

**正确做法**：**先备份**，再联系管理员按流程处理。

## 需要立刻上报的信号

- 库存出现**负数**
- 同一批次**重复扣料**
- 入库数量**超过**计划台数
- 审计校验不通过（`python manage.py audit-verify` 报错）
