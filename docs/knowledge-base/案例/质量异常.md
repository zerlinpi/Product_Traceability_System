# 案例 · 质量异常

## 什么是质量状态

| 状态 | 含义 | 能入库吗 |
| --- | --- | --- |
| **待检** | 已登记，还没处理 | ❌ 不能 |
| **已放行**（PASSED） | 质量合格 | ✅ 能 |
| **暂扣**（HOLD） | 有问题，暂停 | ❌ **不能** |
| **作废**（VOID） | 已作废 | ❌ 不能 |

> **质量门禁是系统强制**：暂扣批次去入库会被**直接拒绝**，
> 不是「提醒一下」。

## 暂扣一个批次

1. **批次管理 → 批次质量处理**
2. 找到批次，点 **暂扣**
3. **必须填原因**（如「外观检查不合格」）

> 原因会记进**审计记录**，后面查得到。

## 暂扣后会发生什么

| 影响 | 说明 |
| --- | --- |
| 不能入库 | 扫码枪入库会被拒绝，并显示暂扣原因 |
| 不影响已登记的台数 | 登记记录保留 |
| 留下审计 | 谁暂扣的、什么时候、为什么 |

## 解除暂扣（放行）

质量问题处理完之后：

1. **批次管理 → 批次质量处理**
2. 找到该批次，点 **合格放行**
3. 之后才能入库

> 放行**也会记录审计**。谁放的、什么时候，都查得到。

## 这批料有问题，要查影响范围

**这是正向追溯的用途**：

1. 打开 **基础资料 → 供应商** → 找到该零部件 → 打开出问题的**到货批次**
2. 点 **正向追溯**
3. 列出**所有用了这批料的成品批次**

> 一次查出全部受影响产品，不用一个个问。

## 反向确认：这个批次用了什么料

**历史记录 → 扫码查询** → 扫批次二维码 → 看**反向追溯**：

- 用了哪些部件
- 哪家供应商、哪个批次
- 消耗了多少（= 登记台数 × 每套用量）

## 完整处理流程

```
发现质量问题
   │
   ├─ 1. 批次质量处理 → 暂扣（填原因）
   │
   ├─ 2. 扫码查询 → 反向追溯，确认用了哪些料
   │
   ├─ 3. 供应商 → 到货批次 → 正向追溯，查出受影响成品
   │
   ├─ 4. 排查问题料，处理
   │
   └─ 5. 批次质量处理 → 合格放行 → 扫码枪入库
```

## 常见问题

| 问题 | 处理 |
| --- | --- |
| 暂扣后想直接入库 | 不行，**必须先放行** |
| 忘了暂扣原因 | 审计记录里有 |
| 放行错了 | 可以再暂扣（会再记一条审计） |
| 批次显示「待检」不能入库 | 先去质量处理放行 |
| 找不到批次 | 用搜索框按批次码找；列表只显示最新 500 条 |

## 需要立刻上报的信号

- 大量批次同时出质量问题（可能是来料批次问题）
- 已入库的批次事后发现质量不合格
- 质量状态被非预期地改动
