# 08 · 备份与恢复

## 备份里有什么

`backup` 生成的是**一组**文件：

| 文件 | 内容 | 何时产生 |
| --- | --- | --- |
| `traceability_<时间戳>.db` | 数据库快照 | 总是 |
| `traceability_<时间戳>.db.images.zip` | **产品图片** | 数据库里有图片时 |
| `traceability_<时间戳>.db.manifest.json` | 校验清单（SHA-256、结构版本、记录数、图片数量） | 总是 |

> ⚠️ **数据库和图片必须一起复制**。少了 `.images.zip`，恢复后数据库里的图片引用
> 会**全部失效**——产品资料页变成一堆破图，而数据本身看不出异常。

## 创建备份

```bash
python manage.py backup
```

输出会告诉你备份文件、图片数量、大小与自检结果。

保留份数：

```bash
python manage.py backup --keep 30
```

> 备份会**自动清理**超出保留份数的旧备份，**图片归档也会一起删**。

## 校验备份

```bash
python manage.py verify-backup exports/backups/traceability_20261009T090000_0800.db
```

期望输出：

```
校验：exports/backups/traceability_20261009T090000_0800.db
    结构版本  22
    自检      ok
    SHA-256   3da4b315...
    产品图片  128 个文件（归档已校验）
[OK] 备份可用
```

> **`产品图片` 那一行必须确认**。若显示「该备份不含图片归档」，
> 而你的产品确实有图，**说明备份不完整**，不要用它恢复。

## 恢复

```bash
python manage.py restore exports/backups/traceability_20261009T090000_0800.db --yes
```

**恢复会做什么**：

1. 先核对 SHA-256——装回去的必须是当初备份的那一份。
2. 把**当前数据库**另存为「恢复前副本」（可回滚）。
3. 把**当前图片目录**移到 `product-images.pre-restore`（可回滚）。
4. 装回数据库与图片。

> **必须加 `--yes`**，避免误操作。

### 恢复后核对

```bash
python manage.py integrity-check     # 期望：[OK] 通过
python manage.py db-info             # 期望：结构版本 22
```

再确认图片目录非空，然后启动服务，登录后抽查：
产品图能显示、批次能查到、库存数量对得上。

## 异机副本（**必做**）

用 rsync 或 robocopy **整目录**同步 `exports/backups/` 到另一台机器或网络盘。

> **不要**改成只挑 `.db` 复制——那会把图片丢在源机器上。
>
> **同一块盘上的备份不能抵御磁盘损坏。** 至少保留：本机一份 + 异机一份。

## 每日自动备份

- **Linux**：crontab 每天 02:30 执行 `manage.py backup --keep 30`
- **Windows**：计划任务执行同样的命令（详见 `docs/BACKUP_RESTORE.md`）

## 恢复演练（建议每季度一次）

1. `python manage.py backup` 生成一份。
2. `python manage.py verify-backup <文件>` 确认可用。
3. 停服务，`python manage.py restore <文件> --yes`。
4. `integrity-check` + 抽查页面。
5. **记录**：日期、文件名、校验结果、抽查结果、执行人。

> 一份**没人恢复过**的备份只是假设，不是安全网。
