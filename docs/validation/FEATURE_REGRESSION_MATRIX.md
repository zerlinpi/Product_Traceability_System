## 三、用户可见的变化（全部）

只有两处，且都**不改变任何操作方式**。

### 1. 列表超过 500 条时会显示提示（新增）

| 项 | 说明 |
| --- | --- |
| **触发条件** | 列表结果超过 500 条（批次登记记录、采购订单、生产订单、入库记录、来料批次） |
| **页面表现** | 表格上方出现黄色提示条：「仅显示最新 500 条，共 N 条」 |
| **数据是否丢失** | **不丢**。导出仍是全量；用筛选可访问更早的记录 |
| **为什么要加** | 后端已限制返回条数，但前端原先不提示，用户会以为记录不见了 |
| **需要学新操作吗** | **不需要**。只是多了一行说明 |

### 2. 领星超时后的提示更准确（措辞变化）

| 情况 | 修改前 | 修改后 |
| --- | --- | --- |
| 领星明确拒绝 | 「推送失败」+ 具体原因 | **不变** |
| 网络不通（请求没发出去） | 「推送失败」 | **不变** |
| **超时（可能已写入）** | 「推送失败」，引导直接重推 | 「**结果未知**：请求已发出但未收到回复，领星可能已经写入。请先在领星按单号核对，确认不存在后再重试。」 |

> **这是安全性的提升**：修改前，超时会被当成失败并**自动重发最多 3 次**，
> 若首次实际已成功，会在领星产生**重复采购单**。修改后写操作不再自动重试。

## 五、API 变更明细

**没有破坏性变更。** 唯一变化是列表接口新增**响应头**（响应体形状不变）：

| 响应头 | 含义 | 不读会怎样 |
| --- | --- | --- |
| `X-Total-Count` | 筛选后总行数 | 无影响，与从前行为一致 |
| `X-Returned-Count` | 本次返回行数 | 同上 |
| `X-List-Limit` | 生效的窗口大小 | 同上 |

**参数变化**：列表接口新增**可选**的 `limit` / `offset`。
不传时使用默认窗口（500），传入非法值返回 400 并指明字段。

**导出接口不受影响**：仍返回全部匹配数据。
